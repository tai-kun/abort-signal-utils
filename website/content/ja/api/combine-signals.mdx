---
title: "シグナルの結合"
description: "combineSignals と combineSignalsFast の仕様と使い分けです。"
---

複数の `AbortSignal` を 1 つに束ねます。`AbortSignal` 以外は無視するため、任意の中断元は選別せずに渡せます。

## 使い分け [#comparison]

| 関数 | 返すもの | 向き |
| --- | --- | --- |
| `combineSignals` | 常に新しいシグナル | 既定はこちら |
| `combineSignalsFast` | 単一なら入力をそのまま返す | 単一が多いホットパス |

独立したオブジェクトが必要なら `combineSignals` を使ってください。`Fast` が返す単一シグナルは元のオブジェクトと同一であり、区別できません。

```ts
import { combineSignals, combineSignalsFast } from "abort-signal-utils";

// 既定
const s1 = combineSignals([a, b]); // 常に新規
// 最適化したいときだけ
const s2 = combineSignalsFast([a]); // a と同一
```

## combineSignals [#combine-signals]

```ts
import combineSignals from "abort-signal-utils";

const combined: AbortSignal = combineSignals(signals, options);
```

    signals: {
      type: "readonly unknown[]",
      required: true,
      description: "束ねる値の配列。AbortSignal 以外は無視します。",
    },
    options: {
      type: "CombineSignalsOptions",
      description: "結合の後始末の選択肢。cleanupSignal 以外は無視します。",
    },
  }}
/>

仕様は次のとおりです。

- 入力のいずれかが中断すると、最初に中断した理由で中断します。
- 中断済みが含まれていれば、即座にその理由で中断します。複数ある場合は、先頭側の中断済みを優先します。このとき `cleanupSignal` には触れません。
- 有効なシグナルがなくても、未中断の新しいシグナルを返します。このとき `cleanupSignal` には触れません。
- 呼び出すたびに独立した新しいシグナルを返し、入力配列は変更しません。
- `AbortSignal.any` がある環境では委譲し、ない環境では同等の代替実装で束ねます。ただし、未中断の `cleanupSignal` がある場合は、環境にかかわらず代替実装で束ねます。未中断の `cleanupSignal` を指定したときは、どの環境でも同じ解除挙動になります。
- 結果が未中断である間は、入力への購読が残ります。入力の中断により結果が中断すると、入力と `cleanupSignal` の購読を解除します。
- `cleanupSignal` の中断では結果は中断せず、未中断のまま残ります (`aborted` は `false`、`reason` は `undefined` のままです)。入力の購読を止めるため、以後の入力の中断は伝わりません。
- `cleanupSignal` が未指定・中断済みの場合は、従来どおり入力のみを束ねます。中断済みの `cleanupSignal` を渡しても、入力への購読は通常どおり残ります。入力と `cleanupSignal` に同一のオブジェクトを渡した場合、中断時は入力として扱います。

```ts
import { combineSignals, timeoutSignal } from "abort-signal-utils";

const stop = new AbortController();
const combined = combineSignals([stop.signal, timeoutSignal(5_000), undefined]);

stop.abort("user-stop"); // combined.reason は "user-stop" になります。
```

:::warning
代替実装で束ねた結果が未中断である間は、入力への購読が残ります。入力の中断か `cleanupSignal` の中断で残りません。`AbortSignal.any` に委譲した場合は、この購読は発生しません。結合が不要になったら、`cleanupSignal` の中断で購読を解除してください。
:::

結合の後始末を別のシグナルに連動させる場合は、`cleanupSignal` を渡します。結合が不要になった合図で中断してください。

```ts
import { combineSignals, timeoutSignal } from "abort-signal-utils";

const cleanup = new AbortController();
const combined = combineSignals([userSignal, timeoutSignal(5_000)], {
  cleanupSignal: cleanup.signal,
});

// 結合が不要になったら、中断して購読を解除します。
// combined は未中断のまま残り、以後の入力の中断は伝わりません。
cleanup.abort();
```

## combineSignalsFast [#combine-signals-fast]

```ts
import { combineSignalsFast } from "abort-signal-utils";

const combined: AbortSignal = combineSignalsFast(signals, options);
```

選択肢の意味は `combineSignals` と同じです。仕様は次のとおりです。

- 有効なシグナルが 1 つだけの場合でも、未中断の `cleanupSignal` があるときは、`combineSignals` に委譲して新しいシグナルを返します。`cleanupSignal` の中断で購読を解除できます。
- 有効なシグナルが 1 つだけで、`cleanupSignal` が未指定・中断済みのときは、新しい割り当てなしでそれ自体を返します。中断済みの入力は `cleanupSignal` に触れずそのまま返します。
- 有効なシグナルがなければ、未中断の新しいシグナルを返します。このとき `cleanupSignal` には触れません。
- 有効なシグナルが 2 つ以上あれば、`options` を含めて `combineSignals` に委譲します。

```ts
const single = combineSignalsFast([controller.signal, undefined]);
console.log(single === controller.signal); // true
```

:::warning
返された単一シグナルは元のオブジェクトと同一です。後から「結合結果だけ中断したい」といった区別はできません。独立性が要る場合は `combineSignals` を使ってください。
:::

## 理由の引き継ぎ [#reason]

中断理由は値のまま伝わります。`Error` は同一インスタンスを保ち、`null` や `0` などの falsy な値も潰しません。理由なしの中断では、実行環境の既定の `AbortError` が伝わります。

```ts
const err = new Error("boom");
const c = new AbortController();
c.abort(err);

const combined = combineSignals([c.signal]);
console.log(combined.reason === err); // true
```
