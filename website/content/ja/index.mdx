`AbortSignal` の定型処理を切り出した、小さな ESM ライブラリーです。複数のシグナルを 1 つに束ねる処理や、中断済みかどうかを確かめる処理、中断を `Promise` として待つ処理などを、古いランタイムでも同じ書き方で扱えます。

## できること [#features]

| したいこと | 使う関数 |
| --- | --- |
| 複数のシグナルを 1 つにまとめる | `combineSignals` / `combineSignalsFast` |
| 中断理由を取り出す | `getAbortReason` |
| 中断済みなら理由を投げる | `throwIfAborted` |
| 指定時間後に中断するシグナルを作る | `timeoutSignal` |
| 中断を `Promise` として待つ | `toAbortPromise` |
| 処理と中断を競争させる | `withSignal` |

`withSignal` を除き、いずれも `AbortSignal` 以外の値を渡してもエラーになりません。`undefined` や `null` が混ざる可能性のある引数は、そのまま配列や引数に入れてください。選別や分岐は不要です。`withSignal` の `signal` には `AbortSignal` を渡してください。

## 最小例 [#quick-example]

```ts
import { combineSignals, throwIfAborted, timeoutSignal, toAbortPromise, withSignal } from "abort-signal-utils";

const userController = new AbortController();
const combined = combineSignals([userController.signal, timeoutSignal(5_000)]);

async function run(signal: AbortSignal): Promise<void> {
  throwIfAborted(signal); // 中断済みならここで理由を投げます。
  await Promise.race([
    fetch("/api/items", { signal }),
    toAbortPromise(signal), // 中断されると、その理由で拒否されます。
  ]);
}
```

中断理由は文字列や `Error` だけでなく、`null` や `0` などの falsy な値もそのまま引き継ぎます。値の有無ではなく、中断した事実で分岐してください。

処理の実行まで含めて競争させる場合は `withSignal` を使います。

```ts
import { withSignal } from "abort-signal-utils";

await withSignal(signal, () => job());
```

## インストール [#install]

```package-install
npm i abort-signal-utils
```

```ts
import {
  combineSignals,
  combineSignalsFast,
  getAbortReason,
  throwIfAborted,
  timeoutSignal,
  toAbortPromise,
  withSignal,
} from "abort-signal-utils";
```

ESM 専用で、副作用はありません。バンドラーでも Node.js でも、そのまま読み込めます。

## 対応環境 [#compatibility]

`AbortSignal.any` と `AbortSignal.prototype.throwIfAborted` がある環境ではネイティブ実装に委譲します。ない環境では同等の代替実装で動きます。実行のたびに対応の有無を判定するため、ポリフィルを後から足してもそのまま使えます。

`timeoutSignal` は `AbortSignal.timeout` がある環境では、条件がそろえば委譲します。ない環境では代替実装で動きます。
